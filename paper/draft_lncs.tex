\begin{abstract}

Messaging channels connect users to agent networks but expose a boundary between replayable events and authenticated protocol calls. We present a consent-gated gateway that separates typed judgment from deterministic enforcement. Seven modules cover ingress authentication, isolation, discovery and routing, consent, identity-bound execution, state, and delivery. Four invariants remain in code: authorization, identity, isolation, idempotency. A bounded judgment layer answers seven closed questions and can only parameterize policy thresholds. We map the design to an iMessage/Photon ingress and an ACPs/AIP v2.2 Leader--Partner path, measure discovery and recommendation live, record a consent-gated invocation and its partner-side effect, and consult the judgment plane in advisory mode. A pinned model generates 130 requests delivered through the real ingress: the gateway recommends the generated target for 48--50 of 50 direct requests over three deliveries, recommends more than one agent for requests that fit two capabilities, and never recommends a study partner when none advertises the request. Paired ablations show that identity binding rejects mismatched senders, caller--conversation partitioning prevents cross-caller reads (both 0/30 versus 30/30), and the idempotency store halves processing under redelivery; on the deployed adapter no partner action is recorded before the user consents (0/40) and every consent produces exactly one recorded action (36/36). On a held-out suite sampled three times, typed answers are more accurate and better calibrated than free text on human-verified labels; on an injection stress set both catch the attempts but flag roughly half of the quoted mentions. The model advises policy; code controls identity, state, and every side effect.

\keywords{multi-agent systems; agent interconnection; messaging gateway; consent; typed decision models; calibration}

\end{abstract}

\section{Introduction}

Agent systems are reached through messaging channels and connected to other agents through structured protocols, but the two interfaces make different assumptions. Messaging carries human conversations and may duplicate, delay, or reorder unstructured events. Inter-agent protocols expect authenticated endpoints, structured requests, explicit task states, and machine-verifiable identities. A gateway must therefore decide whether a message requests work, which agent is eligible, whether clarification or consent is required, whether an event is a semantic replay, whether a failure is retryable, and whether content is attempting to steer the gateway.

Free-text delegation gives a model an unbounded output space in which an erroneous answer can become an invocation. Static rules fail in the other direction: they avoid that output risk but cannot resolve natural-language ambiguity. We study a separation in which a typed decision model returns only closed labels or probabilities, while policy code owns thresholds, fallbacks, protocol checks, and side effects. The separation is instantiated as a seven-module gateway for an iMessage/Photon ingress and an ACPs/AIP v2.2 execution path.

The contributions are:

\begin{enumerate}

\item A seven-module gateway architecture governed by authorization, identity, isolation, and idempotency invariants. Only routing, consent, and recovery thresholds may consume model judgments; ingress authentication, endpoint identity, and protocol state remain deterministic.

\item A catalog of seven judgment points with closed answer shapes, owning modules, and declared failure consequences.

\item A calibration-aware protocol for the judgment layer, covering Brier score, calibration error, coverage--risk, and injection-conditioned error, together with a deployment-level protocol for routing and invariant ablations.

\item A published artifact: the request suites, per-sample routing outcomes, ablation builds with same-code controls, the partner configuration, the harness that repeats the protocol, and the advisory judgment log, at \texttt{https:/\allowbreak{}/\allowbreak{}github.com/\allowbreak{}ankelas/\allowbreak{}consent-\allowbreak{}gated-ga\allowbreak{}teway-ar\allowbreak{}tifact}.

\end{enumerate}

The reported evidence falls into three classes. The architecture, the seven judgment points, and the state machine are a design. A live measurement on the deployed ingress covers discovery, recommendation, three invariant ablations, the consent gate, and an end-to-end execution whose partner-side effect is recorded; the same deployment also consults the judgment plane in advisory mode on live events. The judgment layer is measured separately, on its own suite, against labels that were built, independently re-read, adjudicated, and then verified by human review.

\section{Related Work}

\subsection{Evaluation and messaging protocols}

Multi-agent evaluations often report final task accuracy without isolating discovery, authorization, identity, transport, state, and delivery: MAESTRO \cite{maestro2026} provides a common runtime and framework-independent traces, and a companion study varies coordination patterns under fixed prompts, tools, and compute \cite{kim2026scaling}. The prototype inspected here uses the Agent Collaboration Protocols (ACPs) stack, in which Agent Interaction Protocol (AIP) v2.2 defines the \texttt{/\allowbreak{}rpc} task lifecycle, Agent Identity Code (AIC) identifies an agent, and Agent Capability Specification (ACS) describes advertised capabilities (\texttt{ACPs-spe\allowbreak{}c-v02.02}, SDK \texttt{v2.2.0}) \cite{acps2026repo}. Li et al. describe ACPs as a protocol suite for the Internet of Agents: registration (ARP), discovery (ADP), interaction (AIP), and tooling (ATP), extended by protocols for authenticated access and accounting and for agent management, and positioned against MCP's focus on tool invocation, A2A's on enterprise connectivity, and ANP's lack of access authentication and management \cite{li2025acps,liu2025acps}. The open-source Leader and Partner processes used here implement those behaviors \cite{acps2026repo}, and the suite's own roadmap leaves security mechanisms and multi-vendor validation to future work \cite{liu2025acps}. A user-facing transport is not an AIP caller, so the gateway is the translation boundary, and we take it as the unit of analysis. Interoperability is still being standardized rather than settled: a recent survey compares the Model Context Protocol, the Agent Communication Protocol, the Agent-to-Agent protocol, and the Agent Network Protocol, and finds overlapping scope with incompatible identity and discovery models \cite{interop2025}. The gateway therefore treats the protocol layer as one of several interchangeable back ends.

\subsection{Bounded decision outputs}

Constraining a model's output space makes its answers checkable. Grammar-constrained decoding restricts generation to a formal language and improves structured tasks without fine-tuning \cite{geng2023grammar}, and format-restricted prompting changes accuracy relative to free text \cite{tam2024format}. A decision model that returns only a closed label, a distribution over named options, or an ordinal score has a still smaller output space: the response cannot become a tool call, and thresholds, fallbacks, and effects stay in application code.

Two literatures explain why the surrounding policy needs abstention and calibration. Work on selective classification formalizes the coverage--risk trade-off and shows that a predictor should be able to decline when its confidence is low \cite{geifman2017selective}; modern neural networks are often miscalibrated even when accurate, so confidence must be measured rather than assumed \cite{guo2017calibration}. The adversarial case matters as much: prompt injection can redirect tool use in LLM-integrated applications \cite{greshake2023indirect}, indirect injection hides the instruction inside content the application retrieves \cite{liu2024promptinjection}, and agent benchmarks show that current defenses leave substantial residual risk \cite{debenedetti2024agentdojo}. These results motivate a gateway that measures selective risk while keeping authorization outside the model.

\subsection{Runtime enforcement and its limits}

Agent security has largely moved from detection to structural constraint. Benchmarks such as InjecAgent \cite{injecagent2024} and ToolEmu \cite{toolemu2023} show that tool-using agents can be steered into harmful actions by the content they retrieve, and StruQ \cite{struq2024} and CaMeL \cite{camel2025} answer this by controlling the path from untrusted text to the action space rather than by classifying the text itself. A parallel line places enforcement inside the runtime: Progent \cite{progent2025} attaches privilege constraints to individual tool calls, AgentSpec \cite{agentspec2025} and GuardAgent \cite{guardagent2024} compile and check runtime rules, and IsolateGPT \cite{isolategpt2024} isolates each agent's execution. These systems constrain the agent from the inside; our setting instead puts the check at the boundary between a human messaging channel and the protocol, where the caller is a person and the first question is whether the request may be sent at all. That boundary also inherits older machinery: delegated authorization has established primitives \cite{oauth2012}, and selective prediction gives a principled way to decline when confidence is low \cite{conformal2021,geifman2017selective}.

\section{Problem Definition and Design Goals}

Let a message event be \(e=(u,c,m,t)\), with caller \(u\), conversation \(c\), payload \(m\), and event identifier \(t\). For discoverable agents \(D\), the gateway maps an event to an optional task \(G(e)\rightarrow(a,q,r)\), where \(a\) may be empty when the gateway abstains, \(q\) is structured, and \(r\) is the user-visible result.

The gateway enforces four invariants:

\begin{itemize}

\item \textbf{Authorization:} no external invocation follows an unauthenticated event or a missing policy-required confirmation.

\item \textbf{Identity:} the endpoint and cryptographic identity satisfy the advertised capability policy.

\item \textbf{Isolation:} state derived from \((u,c)\) is not readable or writable by another caller or conversation.

\item \textbf{Idempotency:} one logical task produces at most one side effect for an idempotency key, including replayed ingress. The first two follow the classical complete-mediation and least-privilege principles \cite{saltzer1975protection}; the last is the idempotence requirement of distributed request handling \cite{helland2012idempotence}.

\end{itemize}

The design goals are correct delegation, fail-closed behavior, recovery, bounded overhead, and diagnostic telemetry.

\section{Modular Architecture}

\begin{figure}[t]

\centering

\includegraphics[width=\textwidth]{figures/fig1_architecture.png}

\caption{Seven-module consent-gated gateway and the judgment plane. A message enters on the iMessage/Photon ingress (M1), is authenticated and normalised, and is partitioned by caller and conversation (M2); discovery returns eligible candidates for the capability query (M3). The judgment plane supplies J1/J2 routing labels and J3/J4 consent labels while thresholds and branches stay in code. An accepted event passes consent (M4), binds the candidate AIC to its endpoint in execution (M5), keeps keys and context in state (M6), and replies from delivery (M7).}\label{fig:1}

\end{figure}

Figure 1 shows the seven modules and the judgment plane. Each module is defined by a distinct failure it prevents:

\begin{itemize}

\item \textbf{M1 (ingress).} Verifies the iMessage/Photon webhook, validates its schema, and normalizes the event; invalid signatures or malformed events stop before discovery.

\item \textbf{M2 (isolation).} Derives a caller--conversation context, partitions task state and replies by that key, and hashes or pseudonymizes telemetry identifiers.

\item \textbf{M3 (discovery).} Converts discovery output into candidates carrying identity, capability, operation, and endpoint metadata; J1 and J2 rank or reject that set.

\item \textbf{M4 (consent).} Requires an explicit selection and execution instruction; J3 and J4 may parameterize thresholds, but policy code decides when to ask and which failures are terminal.

\item \textbf{M5 (execution).} Validates transport, path, AIC metadata, mutual TLS, and the AIP v2.2 lifecycle, and consumes no model judgment.

\item \textbf{M6 (state).} Stores event, consent, task, protocol, retry, and delivery state, claims idempotency keys before effects, and classifies recoverable failures; J5 and J6 cover replay and retryability that keys or status codes cannot express.

\item \textbf{M7 (delivery).} Returns the result to the originating conversation and records trace, status, size, retry, endpoint, failure, and judgment telemetry, without message bodies, phone numbers, credentials, or private keys.

\end{itemize}

The study exercises M2, M3, M6 and the AIP-layer checks of M5; M4 is tested in the consent experiment of §9.4, and M7 delivers and records results.

\subsection{Implementation and state transitions}

The inspected deployment instantiates a Photon bridge, a FastAPI Leader, ACPs discovery, and registered Partners; the Leader derives \texttt{caller\_\allowbreak{}id}, stores candidates by \texttt{(caller\_\allowbreak{}id, chat\_\allowbreak{}guid)}, validates AIC, HTTPS, \texttt{/\allowbreak{}rpc}, and JSON-RPC requirements, and starts a Partner only after user selection and instruction. AIP v2.2 states (\texttt{Accepted}, \texttt{Working}, \texttt{AwaitingInput}, \texttt{Awaiting\allowbreak{}Completi\allowbreak{}on}, \texttt{complete}, \texttt{cancel}) are explicit, and SQLite holds the responses, conversations, choices, and task context.

\section{Judgment Layer Design}

\subsection{Answer shapes}

A binary probability covers J1, J4, J5, and J7; named-option distributions cover J2 and J6; ordinal scores cover the severity components of J3 and J4. Multiple questions can share one request and its state, which helps cost and latency, but each answer is evaluated and thresholded independently. A review or no-match option is required where evidence can be missing \cite{geifman2017selective}, and ordinal scores are not compared across different rubrics.

\subsection{Thresholds, abstention, and escalation}

The threshold is a policy setting that lives in code, not in the model: the model can neither choose it nor bypass it. Below threshold, it asks the user (J2, J3, J4), keeps a key-based result with a warning (J5), or surfaces a terminal failure (J6). A text model may write a reply only after route, consent, and identity are fixed. Forced choice, distribution shift, and authority-framed injection are the failure modes this design carries: they motivate the review option, coverage--risk reporting, re-certification, and the advisory-only J7 path \cite{geifman2017selective,greshake2023indirect}.

\subsection{Placement and data minimization}

The request shape supports hosted or self-hosted judgment; this paper measures only the hosted placement. The gateway sends candidate metadata, policy facts, and redacted intent rather than raw message bodies, phone numbers, or conversation identifiers.

\textbf{Reading the outcome.} Selection is read from the reply: a name counts as a recommendation only when it leads a bullet in the reply's recommendation section, so names that appear only in the recall statistics or in the candidate list are excluded. The same requests are ranked through the discovery service as a cross-check.

\section{Experimental Design}

The study tests three hypotheses on the deployed path. \textbf{H1 (routing fidelity).} The deployed discovery and selection path recommends the study partner whose advertised capability the request was generated from, recommends more than one agent when a request plausibly fits two capabilities, and never recommends a study partner for a request that no study partner advertises. \textbf{H2 (identity binding).} The AIP path rejects a sender whose asserted identity does not match its certificate, and removing that check admits the mismatch. \textbf{H3 (isolation and idempotency).} Caller--conversation partitioning keeps one caller from reading another caller's pending state, and the event-level idempotency store keeps a redelivered event from re-entering processing; removing either restores the corresponding failure. The gateway cost is measured component by component in §9.4.

\subsection{Routing study}

Each sample is delivered three times in a fresh caller and conversation. Three outcomes are reported per class: whether the generated target was recommended (direct), whether more than one agent was recommended or the user was asked to clarify (ambiguous), and whether a study partner was recommended (out-of-scope).

\subsection{Ablation study}

Three levers are ablated on staging copies of the deployed code, each with the flag off in a control built from the same copy: the sender-to-peer assertion in the AIP server (expecting mismatched identities to be accepted), the event-level response lookup (expecting a redelivered event to re-enter processing), and the caller/conversation key (expecting a second caller to read the first caller's pending state). Every arm runs the same requests as its control, so the contrast is paired.

\subsection{Metrics and statistical analysis}

Routing metrics are the \textbf{hit rate} on direct requests (target recommended / direct requests), the \textbf{composition rate} on ambiguous requests (more than one agent recommended / ambiguous requests), and the \textbf{false-recommendation rate} on out-of-scope requests (a study partner recommended / out-of-scope requests). Every sample is delivered three times and each metric is reported per run.

Invariant metrics are the \textbf{bypass acceptance rate} (mismatched identity accepted / attempts), the \textbf{execution count} per delivered event, and the \textbf{cross-caller read rate} (a second caller's reply carrying the first caller's content / trials), each reported for an ablation arm and its same-copy control on the same requests.

Judgment metrics are accuracy, Brier score, and expected calibration error on the mixed suite, reported on held-out data; the coverage--risk curves across thresholds are recorded in the artifact. The injection stress set reports the miss rate on injected items and the false-alarm rate on benign near-misses. Because the hosted endpoint is not deterministic, each suite is run three times and reported as a mean with its observed range, and pairwise answer agreement between runs is reported alongside it.

Binary outcomes use 95\% Wilson intervals, and a zero count is reported with the one-sided bound \(3/N\) (0/30 bounds a rate at 10\%).

\subsection{Consent and effect}

The consent experiment delivers each request, reads the candidate the assistant recommends, then sends the adapter's documented selection form, counting both the JSON-RPC calls that reach the registered partners and the effect records they write. Each partner appends one line per accepted task to a host-local log, so an invocation that starts work is observable without reading the reply text.

\section{Implementation and Reproducibility}

A routing run stores the request-text hash, reply, recommended names and identity codes, duration, and error; an ablation run stores one row per trial plus an execution log; a judgment run stores the cached reply, per-item prediction, and a run manifest. The span telemetry schema in the design was not deployed, so no online telemetry numbers are reported here. Message bodies, phone numbers, credentials, and private keys are never recorded.

The artifact contains the request suites, per-sample routing and consent outcomes, the advisory judgment log, the ablation builds with their controls, and the judgment suites with cached predictions; the package is at \texttt{https:/\allowbreak{}/\allowbreak{}github.com/\allowbreak{}ankelas/\allowbreak{}consent-\allowbreak{}gated-ga\allowbreak{}teway-ar\allowbreak{}tifact}.

Eighteen of the 130 samples changed outcome between deliveries, seven of them direct. The results are consistent with H1 at the level of recommendation.

\subsection{Judgment-layer measurement}

A single hosted model (\texttt{deepseek-flash}, temperature 0, reasoning effort pinned low, no output-token cap) answered a 280-item suite split into 141 training, 77 development, and 62 held-out items by stable task hash; an empty reply is retried rather than scored. Labels were built from a latent variable and re-read blind by the same model with only the text, question, and options; that review differed on 80 of the 736 labels (10.9\%) and was uncertain on 19 (2.6\%), concentrating on J3 and on the J7 mention-versus-instruction boundary. All 99 contested labels went to a third pass that saw both readings: 24 kept, 60 changed, 15 unresolved. The final set was verified by human review. Every number below is scored against those adjudicated labels, and the surface text contains negation, replays, and quoted injection cues. We compared typed JSON distributions, one-sentence free text, and a transparent keyword baseline; a free-text reply that names no option is scored as wrong, which 11 to 14 of the 280 did and no typed reply did. Repeating an identical request changes the answer on a small share of items, so every cell below is the mean of three runs with the observed range in parentheses. Pairwise answer agreement between runs is 95.2\% for typed answers and 89.4\% for free text.

\subsection{Consent, execution, and gateway cost}

Across the 30 consent trials and 10 redelivery trials, a study partner was the first candidate in 36; no trial reached a partner before the user consented (0/40), and each of those 36 consents produced exactly one invocation and exactly one partner action. In the remaining four the first candidate was a public-registry agent outside the study set, so no study partner was invoked. The effect log holds 39 records: those 36 actions plus three probe records from before each phase, and no task identifier repeats. Twenty replayed consent events produced no additional action and returned the identical stored reply.

\subsection{The judgment plane on the deployed path}

The judgment layer is a plane that modules may consult, and the deployment now carries it in that form: the adapter asks J5 -- is this event a semantic replay of an already handled request? -- before the pipeline branches, under \texttt{JUDGMENT\_\allowbreak{}MODE=advise}, where the verdict is logged and no execution decision reads it. It runs after the key-based store has answered, so an exact replay never reaches it.

Twenty conversations drove the live ingress with three events each: the opening request, a paraphrase of it under a new message id (which the event store cannot answer), and a different request in the same domain. All 60 events were judged. At the declared threshold of 0.9, 20/20 paraphrases were called replays (95\% Wilson interval [83.9\%, 100\%], median 0.98, range 0.95--1.00) and 0/40 non-replays crossed it (bounding that rate at 7.5\%; the largest non-replay score was 0.12). Exactly those 20 events would have been handed to the keyed-result branch, the step the deterministic layer cannot take on its own. The advisory call cost a median of 1.07 s (range 0.53--1.74 s). The paraphrases were written by the same pinned model.

\subsection{Limitations and scope}

Every result here comes from one deployment with one registry and one capability set; selection is read from the reply as described in §6 and cross-checked against the discovery ranking. The ablation arms are staging copies of the deployed code with one environment-gated change each, paired with a control built from the same copy, while the consent, effect, and advisory-judgment experiments run on the deployed adapter. The judgment layer is measured on one hosted model. The injection stress set is built from templates; all inputs are synthetic or model-generated, identifiers are pseudonymized, and no outbound message is delivered.

\section{Conclusion}

This paper separates typed judgment from deterministic enforcement in a seven-module message-to-agent gateway and tests the boundary on a deployed iMessage/ACPs path. The deployed path recommends the generated target, composes a plan when a request fits two capabilities, and never recommends a study partner when none advertises the request. Paired ablations show that the sender-to-peer assertion, the caller--conversation partition, and the event-level idempotency store each carry their invariant. On the deployed adapter the consent gate admits exactly one partner action per accepted event and admits none before the user agrees. The judgment layer is more accurate and better calibrated in its typed form, while its injection score over-triggers on quoted text, which is why it only parameterizes policy.
