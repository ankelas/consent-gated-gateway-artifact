# 实验部分：问题清单与改进方案

整理日期 2026-10-06。基于当前 `draft.md`（14 页版本）、`experiments/` 与今天的实机探测结果。

## 一、证据结构：最根本的三个问题

### P1 主实验是"自证式"的

`gateway.py` 确实在跑真实代码（HMAC、键控存储、idf 路由、同意门控、端点校验、幂等表），但
**工作负载、故障定义、能力词表、路由温度与阈值全部由我们编写**。因此"移除某模块就暴露对应故障"
是代码结构的回读，不是经验发现。Table 4 里 79.0% / 62.3% / 42.5% 这些数字反映的是生成器参数，
不是被测系统的性质。§11 已承认这一点，但审稿人仍会据此质疑贡献。

### P2 没有任何实机证据

论文在 §8.3、§11、§12.3、§13 四处自述：吞吐、资源竞争、在线协议时延、托管/自托管对比、
人工裁定标签、在线回放 **全部是未来工作**。于是关于"效果"和"安全"的主张没有任何一条落在真实系统上。

### P3 判断层缺少有效性证据

单模型（`deepseek-v4-pro`）+ 生成器写标签 + 未达到 5% 认证目标。标题里的 "Typed Judgment"
目前只有"同一模型下形态差异"的证据，没有人类标签、没有第二个模型、没有部署分布。

## 四、改进方案（按性价比排序）

### 1. 重新定位主实验（低成本、必做）

- 把标题从 "Core Results" 改为 **"Mechanism Regression Test"**，正文动词由"measured/produced rates"
  改为 "the encoded mechanism produced the expected outcome in k/N trials"。
- 摘要与结论删掉 "20,000 arm-level records"，改为 **"4,000 paired tasks replayed under five arms
  (20,000 arm-level runs)"**，让有效 n 一目了然。
- 增加一张 **"What this harness cannot show"** 表（生产失败率、真实攻击成功率、真实时延、模型质量），
  把 §8.3/§11 的散落表述集中起来。

### 2. 判断层补证据（中成本、直接消掉两个 caveat）

- 按 `annotation_protocol.md` 做 **双人标注 + 仲裁**，先在 100–150 条上跑，把 §12.4 的标签来源
  从"生成器"换成"人工裁定"。
- 加 **第二个模型家族**（或自托管），同样 prompt/切分/温度，报告同样指标。两件事都不需要新基础设施。

### 3. 用大模型生成测试样例替代手写模板（中成本、提升外部效度）

- 生成器：固定模型 + 固定 prompt + 缓存，按目标能力域生成消息，并给出**目标 AIC / 歧义 / 超范围**标签。
- 这是外部效度最大的一处改进：手写模板正是 P1 的根源。
- 需要同步做的是**标签独立**：生成器不能同时当评估者（沿用 §12.4 的 split 纪律）。

### 4. 做实机，但只做可测的部分（中成本、需先解决 P9/P13）

可安全实测的：入站完整性、身份绑定强制、幂等（入口层）、隔离（跨调用者/跨会话）、真实分阶段时延。
不可测或已放弃的：同意/副作用（P13）、身份消融（P10）、生产规模。
做法上优先用**适配器注入**（真实管道、无外发），而不是真人发消息。

### 5. 修度量口径（低成本）

- 区分 **correct route / correct invocation / safe abstention** 三个指标，不再互相顶替。
- 需要条件结论的地方（"移除某模块会增加对应暴露"）给**条件率**，分母写清。
- 所有零计数配 3/N 上界；所有时延标注为 cost units，去掉两位小数的伪精度。

### 6. 把归因类发现写成贡献（低成本，且是真发现）

P10（身份绑定独立强制）、P11（幂等落在入口）、P12（会话级缓存）都是实测得到的、可复现的
系统行为事实。它们不依赖大规模实验，却能支撑"边界由代码而非模型控制"这一核心论点。

## 五、建议路径

**若目标是尽快可投**：做 1 + 2 + 5（不动实机），一周内可完成，收益是消掉"自证""无人工标签"
"样本量夸大"三类最容易被拒的问题。

**若目标是补上实机证据**：在 1+2+5 之后做 3 + 4；但必须先解决 P9（把 Partner 接进 Leader 场景，
或改为直接寻址测试）并决定 P13（是否恢复副作用链路）。
